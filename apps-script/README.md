# 抽獎收件端設定

`quiz.html` 的抽獎表單會把資料 POST 到一支 Google Apps Script，由它寫進 Google 試算表。
以下步驟做一次就好，之後換活動也不用重做。

## 1. 建立試算表

1. 開一份新的 Google 試算表，命名例如「115 學年迎新抽獎」。
2. 上方選單 **擴充功能 → Apps Script**。

## 2. 貼上程式碼

1. 把編輯器裡預設的 `function myFunction() {}` 整段刪掉。
2. 貼上本資料夾的 [`Code.gs`](Code.gs) 全部內容。
3. 存檔（Ctrl+S）。

## 3. 部署

1. 右上角 **部署 → 新增部署作業**。
2. 齒輪圖示選 **網頁應用程式**。
3. 設定：
   - **執行身分**：我
   - **具有存取權的使用者**：**所有人**（這項一定要選，否則網頁送不進來）
4. 按 **部署**，第一次會要求授權，依指示允許即可。
5. 複製最後出現的 **網頁應用程式網址**，長得像：
   `https://script.google.com/macros/s/AKfy..../exec`

## 4. 接上網頁

**網址不要寫進任何會 commit 的檔案。** 兩個頁面都從 `assets/config.js` 讀取收件網址，
這個檔案列在 `.gitignore`，不會被推上 git。

**線上網站**（一次性設定）：

1. GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**
   - Name：`APPS_SCRIPT_URL`
   - Secret：`/exec` 網址
2. **Settings → Pages → Build and deployment → Source** 改成 **GitHub Actions**

之後每次推上 `main`，[`.github/workflows/pages.yml`](../.github/workflows/pages.yml)
會在部署時把 secret 寫成 `config.js`。換網址時只要更新 secret，再到 Actions 頁按
**Run workflow** 重新部署即可，不用改程式碼。

**本機測試**：把 `assets/config.example.js` 複製成 `assets/config.js`，填入網址。

## 5. 測試

用手機或無痕視窗開 `quiz.html`，做完測驗、填假資料送出，確認：

- 網頁出現「收到你的報名了！」
- 試算表的「報名資料」分頁多了一列

記得把測試那列刪掉再正式宣傳。

## 這個網址藏得起來嗎？

**可以不進 git，但沒辦法不公開。**

上面的作法讓網址不出現在 repo 與 git 歷史裡。但網站是純前端的靜態頁，瀏覽器要送出資料
就必須知道這個網址，所以部署後的 `assets/config.js` 一定看得到，任何人按 F12 都查得到。

真正該防的是「有人拿這個網址亂灌資料」，所以 `Code.gs` 已經內建：

| 機制 | 擋什麼 |
|---|---|
| 蜜罐欄位 `website` | 自動填表的機器人（真人看不到這個欄位） |
| 必填與格式檢查 | 繞過網頁直接 POST 的空白／亂碼資料 |
| 長度上限 | 有人塞超長字串灌爆試算表 |
| 每分鐘 30 筆上限 | 洗版式的大量送出 |
| `doGet` 不回傳資料 | 有人想用這個網址「讀」報名資料 |

另外注意兩件事：

- **「執行身分：我」** 代表腳本用你的 Google 帳號權限執行，但它只能存取被授權的
  這份試算表，不會影響你其他雲端檔案。
- **試算表本身不要開公開共用**，資料的存取控制是靠它，不是靠網址保密。

### 萬一真的被灌爆

到 **部署 → 管理部署作業 → 封存**，舊網址立刻失效。再建一個新部署、把新網址更新到
`APPS_SCRIPT_URL` secret 並重新部署網站就好，等於換鎖。

git 歷史裡留有幾個早期部署的網址（那時網址還直接寫在 `quiz.html`）。改寫 git 歷史
清不掉別人已經抓走的副本，**把那些舊部署封存掉才真正有效**。

## 三段體驗報名（Tao.html）

`Tao.html` 跟測驗共用同一支腳本與同一個網址，但報名會寫進另一個分頁
**「文昌祈福」**（第一筆送出時自動建立），欄位是：送出時間、姓名、性別（生理男／生理女）、
功德費選項、功德費金額、場次、希望時間。測驗資料仍在「報名資料」分頁，兩邊不會混在一起。

這段是後來加的，**更新 `Code.gs` 後記得重新部署**（版本選「新版本」），否則文昌祈福的報名會被當成測驗資料而被拒收。

## 活動名額（正取／備取）

首頁的報名按鈕會依各 Google 表單目前的回覆數顯示：

| 狀態 | 按鈕 | 提示 |
|---|---|---|
| 正取還有名額 | 點我報名 | 正取剩 N 名 |
| 正取滿、備取還有 | 報名備取 | 正取已滿・備取剩 N 名 |
| 正取＋備取都滿 | 額滿（不能點） | 正取與備取皆已額滿 |

沒有設定名額的活動照舊顯示「點我報名」。人數最多延遲 1 分鐘更新。

每次有人送出表單，腳本會算出他的順位，**寄信通知正取或備取第幾順位**，並記在
「錄取名單」分頁。正取＋備取都滿時，**表單會自動關閉**，拿著連結直接開也填不了。

### 設定（新增活動時重複 2–4）

1. **重新部署**：貼上最新的 `Code.gs`，部署 → 管理部署作業 → 編輯 → 版本選「新版本」。
   這次會多要 Google 表單、寄信、觸發器的權限，照畫面允許即可。
2. **填「活動名額」分頁**（在編輯器執行一次 `installQuotaTriggers` 就會自動建立），每個活動一列：

   | 活動名稱 | 報名連結（網站上的 forms.gle） | 表單編輯網址 | 正取名額 | 備取名額 |
   |---|---|---|---|---|
   | 療癒擴香石 | `https://forms.gle/MRNP9J17k5kt5s8i7` | `https://docs.google.com/forms/d/…/edit` | 20 | 5 |

   - 報名連結要和首頁卡片上的一模一樣，才對得起來。
   - **表單編輯網址**是你自己打開表單編輯時，網址列上 `/forms/d/…/edit` 那串。
     不要貼分享出去的 `/forms/d/e/…/viewform`，那組 ID 腳本打不開。
3. **表單要收集 Email**：在每份表單的 設定 → 回覆 → 收集電子郵件地址，選「回覆者輸入」。
   沒有 Email 也能算名額與關表單，只是寄不了通知（「錄取名單」會註記未寄出）。
4. **掛觸發器**：在編輯器上方選 `installQuotaTriggers` 按「執行」。重複執行不會重複掛。

**表單的擁有者**要是跑這支腳本的那個 Google 帳號，或至少把那個帳號加為表單的編輯者，否則腳本打不開表單。

### 有人取消時

刪掉他在表單裡的回覆，人數就會減少，首頁的剩餘名額也會跟著更新。
但**表單不會自動重新開放**（避免把幹部刻意關掉的表單打開），需要時到表單手動開啟「接受回應」。
備取遞補請依「錄取名單」的順位手動通知。

### 限制

- 免費 Gmail 帳號每天最多寄約 100 封信，超過的會在「錄取名單」記為寄送失敗。
- 一個帳號在同一支腳本最多 20 個觸發器，約等於同時開放 20 個有名額的活動；活動結束後可到
  編輯器左側「觸發條件」刪掉舊的。

## 找不到、打不開收件試算表？

在 Apps Script 編輯器上方的函式下拉選單選 **`checkSetup`**，按 **執行**，
再看下方「執行紀錄」。它會印出試算表的名稱、網址與目前筆數，網址點下去就能開。

看到「這支腳本沒有綁定任何試算表」，表示這支腳本是用「新增專案」建立的獨立腳本，
不是從試算表的「擴充功能 → Apps Script」進去的，所以它根本沒有可寫入的試算表。
兩種修法擇一：

- 照第 1、2 步從**試算表**的擴充功能重新建立一份腳本，重新部署；或
- 開一份試算表，複製網址中 `/d/` 與 `/edit` 之間那段 ID，填進 `Code.gs` 的
  `SPREADSHEET_ID`，重新部署即可。

如果 `checkSetup` 印得出網址但瀏覽器開很久打不開，通常是資料量太大。
先看筆數，若明顯異常（例如幾千筆），大概是被灌了，見下方「萬一真的被灌爆」。

## 常見問題

**送出失敗？**
九成是第 3 步的「具有存取權的使用者」沒設成「所有人」。回到 **部署 → 管理部署作業 → 編輯**（鉛筆圖示）改好，**版本選「新版本」**再部署一次。

**改了 `Code.gs` 卻沒生效？**
Apps Script 要重新部署才會套用。**部署 → 管理部署作業 → 編輯 → 版本選「新版本」→ 部署**。網址不會變。

**電話號碼開頭的 0 不見了？**
程式已在電話前加單引號強制存成文字，不會發生。若是手動貼上的資料才需注意。

**想改欄位？**
同時改 `Code.gs` 的 `HEADERS` 與 `appendRow` 內容，以及 `quiz.html` 裡 `collect()` 回傳的欄位。
